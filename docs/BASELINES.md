# Baselines

Reference scores for the built-in, non-LLM methods. They are deterministic, run in under a second per task, and are
regenerated by:

```bash
piibench baselines                 # or: python -m piibench.run_local --tasks tasks --out results/baselines
```

The full per-task reports are in `results/baselines/` and `results/baselines_hard/`.

## The methods

| Method | What it does |
|---|---|
| `noop` | Changes nothing. Floor: every person leaks. |
| `redact` | Replaces every identifier it detects with `[REDACTED]`. Privacy without identities. |
| `rules-structured` | Schema-aware pseudonymizer for structured person fields only (author, reporter, creator, ...); free text is left alone. |
| `rules` | Links identifiers that share a person object, are identical strings, or where an email's local part equals a username (union-find). Gives each cluster one pool persona, and also replaces those exact strings in free text. |
| `oracle` | Applies the gold. Ceiling, and a test that every task is solvable. |

## Reading the table

* **`redact` scores 0 everywhere, by design.** `[REDACTED]` removes the personal data but also who did what, which
  is what the export is for (continuity 0).
* **`rules-structured` scores 0 on t02 and t05.** It leaves free text untouched, and in those two tasks every
  person is also mentioned in prose. Entity recall is therefore 0, and the harmonic mean is 0 whenever one of its
  components is 0. A method that leaves every person identifiable gets no partial credit.
* **`rules` finds almost every identifier but builds the wrong identity graph.** It cannot connect a GitHub handle
  that shares nothing with the name to its owner, and it gives two people with the same name one persona. On t09
  its entity recall is 1.00, but only 67% of people come out fully right. On the hard split, where such people are
  the majority, that falls to 58% and 55%.
* **`rules` solves only t01,** the control task, where every alias is derivable from the name and a directory lists
  every person.

These baselines show where the benchmark's difficulty lies: not in finding identifiers, but in deciding which ones
belong to the same person.

## What deliberately broken cleanings score

`python scripts/grader_sanity_table.py --task <id>` scores a task under controlled, intentionally flawed cleanings:

* one missed email;
* two people merged into one persona;
* every link repointed to another record;
* prose deleted;
* invented personas that are not declared;
* real names left in `mapping.json`;
* and more.

The results for t01 and t09 are in `results/grader_sanity_t01.md` and `results/grader_sanity_t09.md`. Every
deviation is penalized on the component it violates ([`DESIGN.md`](DESIGN.md) section 6.6).
